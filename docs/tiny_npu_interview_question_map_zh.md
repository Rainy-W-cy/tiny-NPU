# Tiny-NPU 面试题库页面规划

## 1. 规划目标

本规划用于把现有 Tiny-NPU 学习笔记转换成适合数字 IC 面试的分层题库。项目介绍、简历映射和 PPT 讲稿继续由 A01 保存，不改写为题库；其余页面按照真实面试顺序重新明确职责。

## 2. 页面层级

### 2.1 正式面试主线

| 顺序 | 页面 | 面试层级 | 页面职责 |
|---|---|---|---|
| 1 | A01 项目介绍与简历映射 | 开场 | 一分钟/三分钟介绍、简历边界、PPT 使用方式，原文保护 |
| 2 | A02 完整架构与数据流 | L1 顶层 | 系统组成、软硬件边界、Block 流程和两条推理路径 |
| 3 | A03 微码、调度与控制链 | L2 控制 | Fetch、Decode、Scoreboard、Barrier 和发射边界 |
| 4 | A04 GEMM、脉动阵列与量化 | L2 计算 | 阵列、Tiling、ACC、Requantization、GEMV 和利用率 |
| 5 | A05 KV Cache、SRAM 与性能 | L2 存储 | 存储层次、GQA、Prefill/Decode KV、容量和带宽 |
| 6 | A06 验证、综合与结果证据 | L3 证据 | Golden、Verilator、综合、Implementation、STA 和指标口径 |
| 7 | A07 数字 IC 岗位基础 | L3 八股 | 从项目触发 SRAM、FSM、握手、FIFO、CDC、STA、总线和 UVM |
| 8 | A08 高频追问与模拟记录 | L4 实战 | 实时模拟、压力追问、回答修正和复盘记录 |

### 2.2 支撑证据页

| 页面 | 职责 | 使用方式 |
|---|---|---|
| B01 设计参数与 PPA | 参数、公式、报告版本和指标证据 | 回答 PPA 前核对，不作为开场背诵稿 |
| B02 架构决策与可扩展性 | 架构取舍、瓶颈、DRAM/DMA 和下一版方案 | 完成模块题后进入开放设计题 |
| B03 Bug 复盘 | 真实 Bug 的现象、定位、修复和回归 | 验证面和压力面使用 |

### 2.3 参考知识库

原有 Q1-Q100 和 21 个专题页面全部保留，用于补知识和查公式，不再作为正式模拟面试的顺序。正式面试问题必须从简历和候选人上一轮回答自然展开。

## 3. 统一问题顺序

```text
A01 项目开场
-> A02 顶层架构
-> A03/A04/A05 核心模块
-> A06 指标和验证证据
-> B03 真实 Bug
-> A07 项目关联八股
-> B02 开放设计
-> A08 实时与压力模拟
```

## 4. 页面维护规则

- A01 为受保护页面，不因题库重构而删除或改写正文。
- A02 不再重复完整项目介绍，只从“请讲整体架构和数据流”开始。
- A03-A05 先放简历级问题，再放架构级、实现级和压力级追问。
- A06 只记录可证明的结果，并标明对应 RTL 版本。
- A07 同时包含项目关联八股和独立快问快答。
- A08 不堆知识讲义，只记录真实问答、问题评价和修正版。
- B01-B03 是证据和复盘页面，不与 A02-A07 重复建立完整题库。
- 旧 Q1-Q100 不删除，仅从主复习路线移到参考区。
- 所有序列长度相关问题以当前 `MAX_SEQ=16` 为准。
- KV Cache 参数修改后，PPA 数据必须以重新生成的 Vivado 报告为准。
